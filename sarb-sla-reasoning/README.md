# SARB SLA Reasoning Analysis

## Executive Summary

A raw SLA percentage tells leadership *whether* the Solution Architecture Review Board hit its turnaround commitment, but not *why* it was missed — and a Solution Architect waiting on a business stakeholder for a missing BRD looks identical, on paper, to one who simply didn't deliver on time. This skill reads the logged reason behind every missed SLA and separates genuine business/process delays (missing requirements, confidentiality holds, projects reassigned to a new architect, items SARB itself sent back for more work) from delays that are unexplained or vaguely explained. It then produces two fairer performance numbers — a "Gross" SLA % everyone already tracks, and a "Controllable" SLA % that reflects what the Solution Architect or portfolio could actually have influenced — alongside an interactive dashboard so any SA, portfolio, or reason can be clicked to see the exact list of affected projects. This turns a blunt compliance metric into a defensible, explainable performance and policy conversation.

## Business Process Flow

1. A team member exports the current Solution Architecture Work Queue list from SharePoint to a CSV (or Excel) file — the same type of export used for the base `sarb-sla-report` skill.
2. The export is dropped into the shared `SA\Inputs` folder (or passed explicitly with `--input`), and the skill is run via Copilot CLI (`/sarb-sla-reasoning`) or directly with Python.
3. The tool applies the same in-scope rules as the base SLA report — Projects and standalone Ideas created in the target year, excluding Cancelled records and excluding anything that isn't a Project or Idea (TechPASS, NPD, and SA-prefixed work is explicitly excluded) — and calculates the same Met / Not met / Not yet due status using the 14-day (Project) or 28-day (Idea) SLA window, rolled to the next Tuesday.
4. For every item that missed its SLA, the tool reads the logged reason and sorts it into one of three business categories:
   - **Business-caused** — a genuine dependency outside the Solution Architect's control (a missing business requirements document, undefined scope, a confidentiality/NDA hold, a project that hasn't actually started yet, the item being reassigned to a new Solution Architect who needs ramp-up time, or SARB itself asking for the item to come back later because its own feedback required more work). These misses are removed from the "Controllable" scorecard, the same way an item that isn't due yet is removed from the standard scorecard.
   - **Ambiguous** — a logged reason that doesn't clearly explain the delay (or a brand-new reason text not yet categorized). Still counted against the Solution Architect's controllable performance, but called out separately so it can be reviewed and re-coded.
   - **Undocumented** — no reason was logged at all. Also still counted against controllable performance, and reported as its own data-quality metric, since a missing explanation is a governance gap, not evidence the delay was (or wasn't) the Solution Architect's fault.
5. The tool produces two SLA percentages for every Solution Architect and every Program Owning Portfolio: **Gross SLA %** (the traditional measure, counting every miss) and **Controllable SLA %** (excluding business-caused misses) — so a big gap between the two numbers immediately signals "this person/portfolio is mostly blocked by the business, not underperforming."
6. The deliverable is an interactive HTML dashboard with four clickable charts (SLA by Solution Architect, SLA by Portfolio, missed-SLA reasons, and SLA by Solution Architect for Projects only) plus four summary cards (all not-met items, business-caused, ambiguous, and undocumented). Clicking any bar or card drills straight down to the specific list of affected projects, their logged reason, and category — giving a decision-maker evidence in one click instead of a follow-up data request. Supporting spreadsheets are produced alongside it for offline analysis or reporting.
7. All outputs land automatically in the shared `SA\Outputs\sarb-sla-reasoning` folder, ready to open and share.

## Technical Flow

- **Entry point:** `sarb_sla_reasoning.py`, a Python script run via `py .\sarb_sla_reasoning.py --input "<path>"` (directly, or via the `/sarb-sla-reasoning` Copilot CLI skill). Built on `pandas` for data loading/filtering/aggregation and `plotly.graph_objects` for the interactive bar charts, which are embedded into a single hand-built HTML page (plain HTML/CSS/JavaScript, no separate front-end framework) using `json.dumps` to pass the drill-down dataset to client-side JavaScript.
- **Shared path resolution:** The script inserts `..\_shared` onto `sys.path` and imports `output_dir_for` / `latest_input` from `sa_paths.py`. `--output-dir` defaults to `output_dir_for("sarb-sla-reasoning")` (creating `SA\Outputs\sarb-sla-reasoning` if needed). If `--input` is omitted, `latest_input("*.csv", "*.xlsx")` picks the most recently modified matching file in the shared `SA\Inputs` folder and the script exits with an error if none exists.
- **Source loading (`load_source`):** Reads `.xlsx`/`.xls` via `pd.read_excel(..., dtype=str)` or everything else via `pd.read_csv(..., dtype=str, encoding="utf-8-sig")`, stripping whitespace from column headers so SharePoint export quirks don't break column matching.
- **Scope filtering (`build_analysis`):** Validates the required columns exist, then computes `work_ref_upper` to identify `PRJ` rows and collects every `Idea ID` referenced by a `PRJ` row into `converted_idea_ids`. A row is in scope if it is a `PRJ` row, or an `ID`-prefixed row not already converted, **and** its `Created` year matches the `--year` filter (default: current year), and its `Status` is not `Cancelled`. This mirrors `sarb-sla-report` exactly but additionally guarantees non-Project/Idea work types (TechPASS/NPD/SA) never enter the dataset because they never match the `PRJ`/`ID` prefix check.
- **SLA date math (`expected_sarb_date`):** Identical rule set to the PowerShell skill — `Created + 28 days` for `ID` work refs, `Created + 14 days` otherwise, rolled forward day-by-day until `date.weekday() == 1` (Tuesday). `classify_row` then compares the actual `SARB Approval Date` (if present) or the `as_of` date against the expected date to assign `Met` / `Not met` / `Not yet due`.
- **Reason classification (`classify_reason` + `REASON_CATEGORIES`):** A lower-cased, whitespace-stripped lookup dictionary maps known `SARB Reason` text (`pending brd`, `scope not defined`, `project under nda`, `future start date`, `sa change`, `bring back to sarb`) to `business_caused`, and `initial review` to `ambiguous`. Any reason text not in the dictionary falls back to `ambiguous` (visible rather than silently mis-classified); a blank/missing reason is classified `undocumented`. Only `Not met` rows get a non-empty `Reason Category`. `Controllable Not Met` is `True` for any `Not met` row whose category is **not** `business_caused` — this is the field that separates Gross SLA % from Controllable SLA %. To add a newly observed reason string to a category, edit the `REASON_CATEGORIES` dictionary directly in the script.
- **Portfolio normalization:** `Work Ref: Program Owning Portfolio` has a leading `/Active SBD(/SBD/SBD)?/` path prefix stripped via regex, and blanks become `(No portfolio)`; a missing portfolio column entirely falls back to `(No portfolio)` for every row.
- **Aggregation (`build_group_summary`):** Grouped by Solution Architect, by Portfolio, and (a second time, filtered to `PRJ`-only rows) by Solution Architect again for a Projects-only view that avoids the 28-day Idea window skewing a Project-focused SA's number. For each group: `Gross SLA % = Met / (Met + Not Met Gross)`, `Controllable SLA % = Met / (Met + Not Met Controllable)`, and `Undocumented % = Undocumented Misses / Not Met Gross`, all rounded to one decimal and `None` when the denominator is zero. Sorted ascending by Controllable SLA % so the most at-risk SA/portfolio surfaces first.
- **Reason summary (`build_reason_summary`):** Groups all `Not met` rows by reason text (blank becomes "No reason logged"), counts occurrences, and tags each group with its category label for chart coloring.
- **Drill-down data (`build_drilldown`):** Builds a dictionary keyed by `"SA||<name>"`, `"PORTFOLIO||<name>"`, `"REASON||<text>"`, `"SAPRJ||<name>"` (Projects-only per-SA), `"ALL||Not Met"`, and `"CATEGORY||<label>"`, each mapping to a list of project-level dicts (Project ID, Name, SA, Portfolio, Reason, Category, Status). This whole structure is serialized once with `json.dumps` and embedded directly in the HTML page so drill-downs are instant client-side lookups with no server round-trip.
- **Charting (`make_bar_figure`, `make_reason_figure`):** `plotly.graph_objects.Figure` grouped bar charts (Gross vs Controllable, color-coded red/green) for SA, Portfolio, and Projects-only views; a separate color-coded bar chart for reason counts (green=business-caused, orange=ambiguous, red=undocumented). Each figure is rendered with `.to_html(full_html=False, ...)` and stitched into one page; only the first chart loads the Plotly JS library from the CDN to avoid duplicate downloads.
- **HTML assembly (`build_html`):** Hand-written HTML/CSS plus inline `<script>` that wires `plotly_click` events on each chart and `click` listeners on the four summary cards to a `renderDrilldown()` function, looking up the clicked label in `DRILLDOWN_DATA` and rendering either a flat table (`buildTable`) or, for whole-team/category-wide views, a per-SA grouped table (`buildTableGroupedBySA`) sorted by most not-met projects first.
- **Outputs written:** `sa-sla-reasoning-summary.csv`, `portfolio-sla-reasoning-summary.csv`, `reason-sla-reasoning-summary.csv`, `project-only-sla-reasoning-summary.csv`, and `not-met-detail.csv` via `DataFrame.to_csv`, plus `sarb-sla-reasoning.html` (default name, overridable with `--output`), all written into the resolved `--output-dir` (defaults to `SA\Outputs\sarb-sla-reasoning`).
- **Edge cases handled:** the script errors out clearly if required columns are missing or if no in-scope records exist for the requested year; a zero-row Projects-only subset falls back to an empty frame (`sa_summary.iloc[0:0]`) rather than crashing; any SLA percentage with a zero denominator is reported as `None`/blank instead of raising a divide-by-zero error.

## Inputs

- A CSV or Excel export of the Solution Architecture Work Queue (explicit `--input` path, or auto-detected as the newest `*.csv`/`*.xlsx` file in the shared `SA\Inputs` folder). Required columns:
  - `Created` — record creation date, used for the year filter and SLA clock.
  - `Work Ref` — identifier prefix (`PRJ`/`ID`/other) that determines scope and SLA window.
  - `Idea ID` — used to detect Ideas already converted into a Project.
  - `Status` — used to exclude `Cancelled` records.
  - `SARB Approval Date` — actual approval date, if any.
  - `Work Ref: Solution Architect` — the assigned SA, used for grouping.
  - `SARB Reason` (optional but expected) — the logged reason for a missed SLA, used for reason classification.
  - `Work Ref: Program Owning Portfolio` (optional) — used for portfolio-level grouping; falls back to `(No portfolio)` if absent.
  - `Work Ref: Name` (optional) — used as the project name in drill-down tables.
- Optional `--year` (default: current year), `--as-of` (default: today), and `--output-dir` (default: `SA\Outputs\sarb-sla-reasoning`).

## Outputs

All written to `SA\Outputs\sarb-sla-reasoning\` (or a custom `--output-dir`):

- `sarb-sla-reasoning.html` — the interactive dashboard: four clickable bar charts (SA, Portfolio, Reasons, Projects-only SA) and four summary cards, with click-to-drill-down project tables.
- `sa-sla-reasoning-summary.csv` — per-Solution-Architect Gross SLA %, Controllable SLA %, and undocumented-miss metrics.
- `portfolio-sla-reasoning-summary.csv` — the same metrics grouped by Program Owning Portfolio.
- `reason-sla-reasoning-summary.csv` — count of not-met items per logged reason, with its business/ambiguous/undocumented category.
- `project-only-sla-reasoning-summary.csv` — per-Solution-Architect Gross/Controllable SLA %, restricted to Projects only (excludes standalone Ideas).
- `not-met-detail.csv` — one row per not-met item with its Solution Architect, Portfolio, logged reason, and reason category.
